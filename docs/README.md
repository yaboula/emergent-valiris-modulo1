# Documentation

Documentation is treated as code: every document is versioned, reviewed through pull requests and kept up to date with the product.

| Area | Location | Produced in |
| --- | --- | --- |
| Project charter: purpose, quality bar, principles, standards, roles, risks | [`project/charter.md`](project/charter.md) | M0, maintained continuously |
| Current first-product roadmap and milestones | [`project/roadmap.md`](project/roadmap.md) | M0, maintained continuously |
| Glossary (ubiquitous language, EN/ES) | [`glossary.md`](glossary.md) | Continuously |
| Architecture decision records | [`adr/`](adr/README.md) | Continuously |
| Research: market, competitors, 50-review ledger, simulated interviews, legal, synthesis | [`research/`](research/README.md) | Historical discovery; focused checks as needed |
| Product: vision, personas, story map, scope | `product/` | M0 launch commitment; detailed criteria in M2 |
| Software requirements specification | `srs.md` | M0 launch commitment; detailed criteria in M2 |
| Architecture: C4, data model, events, threat model | `architecture/` | M2, updated with construction |
| Design: art direction, design system, flows | `design/` | M1, updated with evidence |
| Testing: strategy, manual test plans, reports | `testing/` | Design checks from M1; construction checks from M3 |

Planning applicability and tracker mapping: [project/planning-transition.md](project/planning-transition.md). The earlier seven-module timetable and gate labels are historical, not current release commitments.
