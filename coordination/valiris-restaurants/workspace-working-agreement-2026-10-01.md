# Working agreement — current repository policy

Updated 3 October 2026 by the owner's explicit decision. The filename is retained for continuity; the [unchanged previous agreement](../history/pre-repository-storage-2026-10-03/workspace-working-agreement-2026-10-01.md) is historical and has no current authority.

Read [AGENTS.md](../../AGENTS.md), [HANDOFF.md](../../HANDOFF.md) and [CONTRIBUTING.md](../../CONTRIBUTING.md). Every specialist works through Git in an isolated worktree/checkout and its own assignment branch. Instructions, prompts, coordination, project deliverables and evidence are versioned in this repository. Confirm the expected repository and branch before staging, committing and pushing; stage only owned paths and preserve concurrent work. Deliver relative paths, commit SHA, PR, checks and remaining dependencies.

The former ban on repository AGENTS/HANDOFF/prompts and operational role records is superseded. Secrets, browser sessions, caches, dependencies and unrelated personal documents are not project deliverables. Tool-generated delivery assets are copied into the repository with provenance and their approval boundary.

Communicate with Yahya in Spanish. Product documentation, commits, issues and PRs remain English; operational coordination and historical originals may retain Spanish. Local commits use Yahya <yaboula@epsa.upv.es>, GitHub squash author retains the same authorised identity, with no trailers or tool signatures. Verify author/trailers after committing. These attribution rules do not prohibit identifying specialist responsibilities in operational instructions and evidence.

Use the existing issue, branch and PR workflow. Keep branch protections active; squash merge only reviewed authorised work. Significant product/architecture decisions use existing ADR practice. Do not close a milestone because its documentation was stored or merged, duplicate the backlog, or presume a specialist/message/review was activated.
